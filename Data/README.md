# Data

`data_gen.get_dataset(name)` returns every dataset of the paper and of the quick start as time-ordered snapshots.
The four synthetic benchmark datasets are generated by code (`data_gen.py`); the other nine datasets are read from
the files in this directory: three toy datasets generated for this repository and six benchmark datasets released
with earlier work, bundled unchanged, losslessly compressed or (embryoid body) cut down to the two arrays the loader
reads.

```python
from data_gen import get_dataset, split_dataset

data = get_dataset('dyngen_tree')            # times (T,), frames: T arrays (n_t, d), truth weights
split = split_dataset(data, held_out=[3])    # withhold snapshot 3 from the fit
```

* The compression is lossless: `gzip -dc Data/citeseq.csv.gz | sha256sum` prints the SHA-256 of `citeseq.csv`
  (likewise for Veres). `-n` leaves the file name and time stamp out of the header, so the commands reproduce the
  bundled bytes (GNU gzip 1.10). pandas reads the `.gz` files directly, with the same parser as the CSV files.
* `eb_phate.npz` keeps the two arrays the loader reads, unchanged: `phate`, (16819, 2) float64, and
  `sample_labels`, (16819,) int64 (SHA-256 of the array bytes `1ec2f944b1fa813dd8f3187d9f272ae145d7095b3b5bd86a7790bbff84091e88`
  and `28a1ef10412e7bc44aafcb9effd4d14bebbc1442e67d4aa3f351a0981110add9`). The other arrays of the original file
  (`pcs`, `pcs_delta`, `delta_embedding`, `color`, `ixs`) are not used. With Python 3.12 and NumPy 2.5 the command
  reproduces the bundled file byte for byte; other versions may write different zip metadata around the same arrays.
* `toy_data.npz` holds `times` (5,) and the three datasets as (5, 256, 2) arrays. It was generated with the
  snippet below (it reproduces the file byte for byte with NumPy 2.5). With fresh noise `N(0, I_2)` for every
  snapshot: `circular` is a blob moving on a half circle; `converging` two blobs merging into one, with an
  independent random side per point and snapshot (the snapshots are not paired); `expanding` a blob that drifts
  while it spreads.

```python
import numpy as np

times = np.linspace(0.0, 1.0, 5)
arrays = {"times": times}
for name in ("circular", "converging", "expanding"):
    rng = np.random.default_rng(17)
    clouds = []
    for t in times:
        noise = rng.standard_normal((256, 2))
        if name == "circular":
            x = 1.5 * np.array([np.cos(np.pi * t), np.sin(np.pi * t)]) + 0.20 * noise
        elif name == "converging":
            side = rng.choice([-1.0, 1.0], size=256)
            x = 0.18 * noise
            x[:, 0] += 1.5 * (1.0 - t) * side
            x[:, 1] += 0.6 * np.sin(np.pi * t)
        else:
            x = np.array([t, 0.5 * np.sin(np.pi * t)]) + (0.15 + 0.65 * t ** 2) * noise
        clouds.append(x)
    arrays[name] = np.stack(clouds)
np.savez_compressed("Data/toy_data.npz", **arrays)
```

## Generated datasets

The four synthetic benchmark datasets are generated on the fly by numpy ports of the generators in `data_gen.py`
of the WLR repository, called with the arguments of the benchmark: `get_diverging_gaussians(200)`
(`data_gen.diverging_gaussians`), `get_diamonds(500, colors=5)` (`data_gen.petal`), `get_converging_gaussian` with
its random thinning factor (`data_gen.converging_gaussian`) and `get_circular_gaussian(10, 10, 100, 0.5)`
(`data_gen.circular_gaussian`). Seed 0 gives the paper's data; `get_dataset(name, seed=s)` gives other draws.

The ports use the same draws in the same order on a private `numpy.random.RandomState(seed)`, so they reproduce the
frames of the original generators bit for bit when both run with the same BLAS kernels. The Diverging Gaussian
frames themselves depend on those kernels in the last bits (numpy's `multivariate_normal` factorises each covariance
by an SVD and applies the factor through BLAS): snapshot t = 1 (the second) differs by up to 4.4e-16 between
OpenBLAS's AVX2 and AVX-512 kernels, and older kernels also change t = 2 and 3 (by up to about 2e-15). The paper's
fits used the AVX-512 variant.

## What the loaders do

* **CSV files of the WLR repository** (`dyngen_tree`, `dyngen_cycle`, `citeseq`): the first column `samples` is the
  time label, the other columns are coordinates. Each time label is subsampled to at most 319 (`dyngen_tree`), 52
  (`dyngen_cycle`) or 1000 (`citeseq`) rows without replacement, with the rule of the WLR loaders
  (`subsample_dataframe(df, k, seed)`): labels in ascending order, rows `permutation(n_label)[:k]` of a
  `numpy.random.RandomState(seed)` (`data_gen.group_sample`; seed 0 by default). `pandas.read_csv` (default parser)
  only reads the file.
* **CSV files of BranchSBM** (`bsbm_mouse`, `bsbm_veres`): every row is used; snapshots are grouped by the `samples`
  column in ascending order; rows keep the file order.
* **Embryoid body** (`eb_phate`): the 2-D `phate` coordinates grouped by `sample_labels`, as in the PACE benchmark;
  the loader applies no normalisation. `split_dataset` **standardises every split with the mean and standard
  deviation (population, per coordinate) of its retained snapshots**, applied to all snapshots including the
  withheld ones, so no statistic of a withheld snapshot enters the model. Training and all scores of this dataset are
  in these standardised coordinates, as in the paper; `split.whitening = (mean, std)` maps them back
  (`x * std + mean`).
* **Times**: `0, 1, ..., T - 1` for the benchmark datasets (the convention of the WLR evaluation) and
  `0, 0.25, ..., 1` for the toy data.
* **Truth weights** (used by the scores): every observed snapshot is a uniform measure. For the datasets that come
  from the WLR repository (the four synthetic ones, `dyngen_tree`, `dyngen_cycle`, `citeseq`) the weight vector
  `full(n, 1/n)` is divided by its sum, as the WLR loaders do; the two rules differ only in the last bit for some
  sizes (e.g. 19, 100, 200 and 1000 points), and the scores use the dataset's rule.
